Valores de interacción

iMoles no define estados de interacción; estos valores son una propuesta derivada de las escalas. Rellenos: hover un paso intermedio (650), pulsado el 700. Superficies (tarjeta, fila, opción): neutro.25 y neutro.100. En táctil, el pulsado es la respuesta principal; el hover solo aplica con puntero.

  • Foco visible: anillo de 2 px en foco.anillo, separado 2 px del elemento. 5,75:1 sobre fondo.pagina (WCAG 1.4.11 y 2.4.7). Igual en todos los componentes, también sobre rellenos de color.
  • Deshabilitado: deshabilitado.fondo + deshabilitado.texto (3,97:1). Exento de contraste, pero se mantiene legible. Sin sombra.
  • Carga: conserva el color del rol y añade indicador en texto.inverso; no pasa a deshabilitado.
  • Seleccionado: seleccion.*; el borde de 2 px y el texto acompañan al color.
  • Velo modal: neutro.950 al 48 % bajo menús y hojas.
  • Enlace: el anillo de foco se ajusta al texto (6 px de margen lateral, radio 2 px) para no confundirse con un botón. El área táctil puede ampliarse hasta 44 px sin cambiar el anillo visible.
  • Insignias y chips de nivel no son interactivos: no tienen estados.

Validación · visión del color

Diferencia perceptual ΔE en OKLab (×100) entre los cinco rellenos, en visión normal y con simulación de deuteranopía, protanopía y tritanopía (Machado 2009, severidad 1) y acromatopsia (solo luminancia). WCAG no fija un mínimo entre colores; exige que el color no sea la única señal (1.4.1). Objetivo práctico: 8 o más. Por debajo, la distinción la garantizan la forma y el texto de la insignia.

Formato de tokens

Decisión para la implementación futura del design system, fuera de este repositorio: aquí no se genera ningún archivo de tokens. Formato del W3C Design Tokens Community Group (DTCG): JSON con $value y $type; los semánticos referencian primitivos con llaves.

{
  "color": {
    "marca": { "600": { "$type": "color", "$value": "#00698C" } },
    "accion": {
      "principal": { "$type": "color", "$value": "{color.marca.600}" }
    }
  }
}
