Valores simples y compuestos

Un token simple guarda un valor; uno compuesto, varios que viajan juntos. Los mixins agrupan las propiedades que siempre se aplican a la vez y de ellos salen las clases utilitarias.

Simple, compuesto y mixin

Un token compuesto se lee en una sola propiedad. Cuando el estilo necesita más de una propiedad, como el tracking y las mayúsculas de type.ui, se agrupan en un mixin.

{n} es el paso de la escala: half, 1 … 9. Los mixins de layout no llevan gap: se combinan con gap-{n}. Los componentes no ponen margin exterior; lo pone la app en su propio layout.

Archivo de mixins

// _mixins.scss · solo lee variables CSS de tokens.css
@mixin t-body { font: var(--ds-type-body); }
@mixin t-ui {
  font: var(--ds-type-ui);
  letter-spacing: var(--ds-type-ui-tracking);
  text-transform: uppercase;
}
@mixin text-secondary { color: var(--ds-color-text-secondary); }
@mixin bg-surface { background: var(--ds-color-bg-surface); }
@mixin r-md { border-radius: var(--ds-radius-button); }
@mixin e-interactive { box-shadow: var(--ds-elevation-interactive); }
@mixin focus-ring {
  outline: var(--ds-focus-ring-width) solid var(--ds-color-focus-ring);
  outline-offset: var(--ds-focus-ring-offset);
}
@mixin stack { display: flex; flex-direction: column; }

$space: half, 1, 2, 3, 4, 5, 6, 7, 8, 9;
@mixin p($n)   { padding: var(--ds-space-#{$n}); }
@mixin gap($n) { gap: var(--ds-space-#{$n}); }

// utilities.scss → utilities.css
.t-body { @include t-body; }
.t-ui { @include t-ui; }
@each $n in $space {
  .p-#{$n}   { @include p($n); }
  .gap-#{$n} { @include gap($n); }
}

// Button.scss · librería
.dsm-btn { @include t-ui; @include r-md;
  &:focus-visible { @include focus-ring; } }

Reglas

  1. Un mixin solo contiene var(--ds-*). Nunca un valor literal ni un primitivo.
  2. Un mixin tiene una sola responsabilidad: tipografía, color, superficie, forma, elevación, espaciado o layout. Las combinaciones se hacen al usarlo, no dentro del mixin.
  3. Cada mixin de uso «Librería y apps» tiene su clase con el mismo nombre. focus-ring no tiene clase: el foco lo resuelven los componentes.
  4. Un mixin nuevo entra solo cuando lo pide un componente o una app (2.3) y se nombra según 2.2.
  5. Caso límite: si un componente necesita la tipografía de un rol con otro color, usa el mixin y el color por separado; no se crea un mixin nuevo.
