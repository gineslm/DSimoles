# Pilot 1 · Decisions to apply to the repository

Date: 2026-10-08 · Origin: pilot session in Claude Design on the repository (then `gineslm/DSiomles@main`, now `gineslm/DSimoles`).
Addressee: Claude Code. Status of each decision in the [registry](README.md).

This document was corrected after applying the pilot. Each decision keeps its original reason and adds a **Status and result** section with what was actually done. Where the original premise turned out to be wrong, it says so.

## D1 · Section pages are created as Design Components (`.dc.html`)
**Status: applied.**

**Reason.** Plain HTML prevents structured editing, variant controls and component reuse across pages in Claude Design.

**Original proposal.** `safePage` accepts `.dc.html`; `guide.json` does not change (the suggested path admits both variants); rule 3 of `CLAUDE.md` allows the vendored runtime; identify the runtime in the first transfer; the iframe sandbox does not change in advance; the `ds-section-id` meta in the `<head>`.

**Status and result.**
- `safePage` and `pageCandidates` accept `.html` and `.dc.html`. If both exist for the same section, `check` fails.
- **Runtime identified:** `support.js` (generated by Claude Design, one per `sections/` folder, identical in all) and React 18.3.1 and React-DOM, which `support.js` downloaded from unpkg. React was vendored in `assets/_runtime/` and each page loads it before `support.js`. `check` verifies the order, that there are no external scripts, that the `support.js` copies are identical and that the runtime's SHA-384 matches the one `support.js` declares. Detail in [data-contract.md](../data-contract.md) and [scripts.md](../scripts.md).
- **Sandbox:** unchanged (`allow-scripts`). The pilot page works inside the iframe without `allow-same-origin`.
- **Unforeseen finding:** inside the iframe, `<sc-for>` and `<sc-if>` as direct children of table elements are not recovered (the runtime repaired them with `fetch(location.href)`, which the sandbox prevents). The page must avoid them and `check` enforces it. The whole page was walked through in the container to verify this; the first review had only looked at the header.
- **Validation with `visuals.color`:** served over HTTP, inside the iframe, `safePage` and `check` all correct. Visual review by a person remains the responsible person's.
- The two `<script>` lines of the runtime are added by hand in every page: Claude Design has no setting that generates them. They are kept in partial edits; a full rewrite would lose them and `check` detects it.
- Windows warning: the vendored runtime and the `support.js` files are marked `-text` in `.gitattributes`, so that `core.autocrlf` does not change their line endings and break the hash.

## D2 · The web container becomes read-only
**Status: applied.**

**Reason.** It is only edited in Claude Design. The site is a snapshot of the repo's state. Editing in the browser created a second editing point, a draft that looked like a save and exports that could overwrite all 132 entries.

**Status and result.** The editable name, import, export, drafts and `sessionStorage` were removed. Status, page, owner, notes and review are shown as text; the status as an R/I/P/N label. Search, combinable filters, expansion, the Guide/Page switch, an iframe with a separate link and the progress bar are kept. README, `data-contract.md` and `quality.md` were updated.

## D3 · `data/project.json` is the central record, edited only by Claude Design
**Status: applied.**

**Proposal.** Claude Design modifies only the affected entries. The page path is deduced from the ID with `suggestedPath` (`.html` or `.dc.html`); `page` only for exceptions. The container checks existence when an item is expanded; `check` requires a page in I and R sections.

**Status and result.** Implemented with `pageCandidates`; the container checks with a `HEAD` request and requires a correct `text/html` response. If there are several simultaneous editors in the future, model B will be considered (status in each page's metadata and a generated `project.json`); today it is not applied.

## D4 · Transfer protocol and guarantees
**Status: applied.**

**Flow.** GitHub is the source of truth; Claude Design reads the repo and fixes an initial state; work happens in Claude Design; Claude Code moves the changes to the local repo; local validation; push.

**Status and result.** Documented in [handoff.md](../handoff.md), [claude-design.md](../claude-design.md) and [claude-code.md](../claude-code.md): base recorded in `github.md`, check at the start of every session, Claude Design's write scope, Claude Code's copy scope, integration by ID, validation and closing the cycle. An unforeseen guarantee was added: **the connector's listing filters files** (it made `scripts/*.mjs` invisible), so it is cross-checked with the paths named by `package.json`, `CLAUDE.md` and the contract, and what is missing is read by path.
