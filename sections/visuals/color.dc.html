Interaction values

iMoles defines no interaction states; these values, derived from the scales, were approved by the owner on 2026-10-10. Fills: hover one intermediate step (650), pressed 700. Surfaces (card, row, option): neutral.25 and neutral.100. On touch, pressed is the main feedback; hover only applies with a pointer.

  • Visible focus: 2 px ring in focus.ring, 2 px away from the element. 5.75:1 on bg.page (WCAG 1.4.11 and 2.4.7). Same in every component, also on color fills.
  • Disabled: disabled.bg + disabled.text (3.97:1). Exempt from contrast, but kept legible. No shadow.
  • Loading: keeps the role color and adds an indicator in text.inverse; it does not switch to disabled.
  • Selected: selection.*; the 2 px border and the text accompany the color.
  • Modal scrim: neutral.950 at 48% under menus and sheets.
  • Link: the focus ring hugs the text (6 px side margin, 2 px radius) so it is not mistaken for a button. The touch area can grow to 44 px without changing the visible ring.
  • Level badges and chips are not interactive: they have no states.

Validation · color vision

Perceptual difference ΔE in OKLab (×100) between the five fills, in normal vision and simulating deuteranopia, protanopia and tritanopia (Machado 2009, severity 1) and achromatopsia (luminance only). WCAG sets no minimum between colors; it requires that color is not the only cue (1.4.1). Practical target: 8 or more. Below it, the badge shape and text guarantee the distinction.

Token format

Decision for the future implementation of the design system, outside this repository: no token file is generated here. W3C Design Tokens Community Group (DTCG) format: JSON with $value and $type; semantic tokens reference primitives with braces.

{
  "color": {
    "brand": { "600": { "$type": "color", "$value": "#00698C" } },
    "action": {
      "primary": { "$type": "color", "$value": "{color.brand.600}" }
    }
  }
}
